# Plugin-Based Authentication System

Fortress now supports a **hot-swappable plugin-based authentication system** that allows authentication methods to be dynamically loaded, updated, and managed without requiring application restarts.

## Overview

The plugin-based authentication system replaces hardcoded authentication implementations with a flexible, extensible architecture that supports:

- **Hot-swapping**: Update authentication methods without downtime
- **Multiple Auth Methods**: JWT, OAuth 2.0, SAML 2.0, Basic, API Key, and custom methods
- **WASM Runtime**: Secure sandboxed execution environment for plugins
- **REST API Management**: Complete API for plugin lifecycle management
- **Zero Downtime Deployments**: Rolling, blue-green, and canary deployments

## Quick Start

### 1. Installation
```bash
# Copy plugin files to plugin directory
cp plugins/auth/*.wasm ./plugins/auth/
cp plugins/auth/*.json ./plugins/config/
```

### 2. Configuration
```rust
use fortress_core::auth_service::{AuthApiManager, AuthApiConfig};

let config = AuthApiConfig {
    plugin_directory: "./plugins/auth".to_string(),
    default_method: AuthMethod::JWT,
    enable_hot_reload: true,
    health_check_interval: 60,
    max_plugins: 10,
};

let auth_manager = AuthApiManager::new(
    Arc::new(PluginAuthService::new(config)).await
).await?;
```

### 3. Basic Usage
```rust
use fortress_core::auth_service::{AuthRequestBuilder};

let request = AuthRequestBuilder::new()
    .with_method(AuthMethod::JWT)
    .with_credentials("user", "password")
    .build();

let result = auth_manager.authenticate(request).await?;
```

### 4. API Usage
```bash
curl -X POST http://localhost:8080/auth \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"method": "JWT", "credentials": {"username": "user", "password": "password"}}'
```

### 5. Plugin Development
See [Plugin Development Guide](#plugin-development) for creating custom authentication plugins

## Plugin Development

### Plugin Interface
```rust
use fortress_core::auth_plugin::*;

#[async_trait::async_trait]
pub trait AuthPlugin: Send + Sync {
    fn metadata(&self) -> &AuthPluginMetadata;
    async fn initialize(&mut self, config: serde_json::Value) -> Result<()>;
    async fn authenticate(&self, request: AuthRequest) -> Result<AuthResult>;
    async fn validate_token(&self, token: &str) -> Result<AuthUserInfo>;
    async fn refresh_token(&self, refresh_token: &str) -> Result<AuthResult>;
    async fn logout(&self, token: &str) -> Result<()>;
    async fn health_check(&self) -> Result<bool>;
    async fn cleanup(&mut self) -> Result<()>;
    fn supported_methods(&self) -> Vec<AuthMethod>;
    fn supports_method(&self, method: &AuthMethod) -> bool;
}
```

### Host Functions
The WASM runtime provides these host functions to plugins:

- `auth_log(level, ptr, len)` - Authentication logging
- `auth_store_session(session_id, session_id_len, user_data_ptr, user_data_len)` - Session management
- `auth_get_session(session_id, session_id_len, out_ptr, out_len)` - Session retrieval
- `auth_delete_session(session_id, session_id_len)` - Session deletion
- `auth_cache_token(token, token_len, user_data_ptr, user_data_len)` - Token caching
- `auth_get_cached_token(token, token_len, out_ptr, out_len)` - Token retrieval
- `auth_generate_token(user_id_ptr, user_id_len, out_ptr, out_len)` - Token generation
- `auth_validate_token(token_ptr, token_len)` - Token validation
- `auth_hash_password(password_ptr, password_len, out_ptr, out_len)` - Password hashing
- `auth_verify_password(password_ptr, password_len, hash_ptr, hash_len)` - Password verification
- `auth_make_http_request(url_ptr, url_len, method_ptr, method_len, body_ptr, body_len, out_ptr, out_len)` - HTTP requests
